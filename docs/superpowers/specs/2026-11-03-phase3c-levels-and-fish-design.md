# Phase 3-C: レベルで変わる餌・釣れる魚、オリジナル魚 設計書

- 親設計書: `2026-11-03-phase3b-fishing-level-design.md`
- 魚のリスト: `docs/superpowers/fish-list.md`(魚・レベル・重量は後で増減してよい。データ駆動にして、変更が JSON と言語ファイルの編集で済むようにする)
- 日付: 2026-11-03
- 2 段で実装する: **前半 = 仕組み**(レベル、餌、抽選)、**後半 = 魚のデータ**(オリジナル魚 56 種のアイテム、JSON、言語、仮画像)。
- 対象外: 魚を焼いて食べる、場所ごとの魚、ポイント変換とスキル(`backlog.md` を参照)。

## 1. レベルと餌

- 魚には `level`(1〜20)、餌には `bait_level`(1〜20)を持たせる。どちらもデータパックの `fish_profiles` JSON に書く。
- 餌の条件: `bait_level` <= 自分の釣りレベル なら使える。超えていれば、餌を使わず(消費もしない)、アクションバーに「このエサは釣りLv.N以上で使えます」を出す(言語ファイル)。
- 餌にできるのは、JSON に `bait_level` を書いたアイテムだけ。
  - ミミズ: `bait_level: 3`、効果なし。
  - オリジナル魚(と、バニラの魚 4 種): `bait_level` = その魚の `level`。釣った魚をそのまま餌にできる。
  - ゴミ、宝物は `bait_level` を書かない(餌にならない)。
- 餌は、従来どおり、竿をメインハンドに持ったときのオフハンドから読み、ファイト終了時に 1 つ消費する(クリエイティブでは消費しない、同じ種類のままのときだけ)。
- ホタル虫と頑丈なペーストは削除する(アイテム、`BaitType` の該当値と効果、モデル、言語、クリエイティブタブ、テスト)。餌の効果は今回なくなる。ミミズも効果なし。

## 2. 釣れる魚の決め方(`CatchSelector`、純 Java)

入力: 抽選プール(`level`、`catch_weight`、アイテム ID を持つエントリ)、狙うレベル T、幸運の合計、餌にした魚のアイテム(なければ null)、乱数。

1. **狙うレベル T**: 餌があれば `bait_level`、なければ 1。
2. **1 つ上の確率** `up = 0.10 + 0.03 × 幸運`(上限 0.5、餌なしのときは 0)。この確率で、まず `T+1` を狙う(`T+1 > 20` ならこの抽選は行わない)。当たらなかった場合は 3 へ。
3. **レベルの選択**: レベル `T - k`(k = 0 以上、レベル 1 まで)のうち、プールにエントリがあるレベルだけを候補にし、重み `0.5^k` で選ぶ。`T+1` を狙って当たった場合も、そのレベルにエントリがなければ 3 の候補選びに回る。候補が 1 つもなければ、プール全体の最も低いレベルを使う。
4. **魚の選択**: 選んだレベルのエントリから `catch_weight`(既定 10)で重み付けして選ぶ。
5. **餌にした魚と同じ種類**: 選ばれたのが餌にした魚と同じアイテムなら、99% は 4 から引き直す(最大 10 回、超えたら採用する)。
6. 結果は `List<ItemStack>`(1 スタック、個数 1)で、従来の `CatchResolver.roll` の戻り値と同じ型にする。バニラの釣りの抽選表は使わない。幸運は、釣り竿の「宝釣り」と釣りの幸運(プレイヤーの LUCK 属性)の合計を、従来と同じ方法で取る。

## 3. データ(`fish_profiles` JSON の追加項目)

| 項目 | 型 | 既定 | 制約 |
|---|---|---|---|
| `level` | 整数 | なし(省略すると釣れない) | 1〜20 |
| `catch_weight` | 整数 | 10 | >= 1 |
| `bait_level` | 整数 | なし(省略すると餌にならない) | 1〜20 |

- `FishInfo` に `Integer`/`OptionalInt` ではなく、`catchLevel`(0 = 釣れない)、`catchWeight`、`baitLevel`(0 = 餌にならない)を足す。`FishProfileParser` に検証とテストを足す。
- `FishProfileLoader` に、抽選プールを返す `pool()` と、アイテムから `baitLevel` を引く `baitLevelOf(ItemStack)` を足す。
- 既存の同梱 JSON(バニラの魚、ゴミ、宝物)に `level` と `catch_weight` を足す。バニラの魚 4 種は `bait_level` も足す。ミミズ用の JSON(`worm.json`、`bait_level` のみ。`item` 以外の既存必須項目は省略可)を足す。

## 4. オリジナル魚(後半)

- バニラ 4 種以外の 56 種を、`ModItems` に登録する(画像は仮)。ID は英語のローマ字(例: `haze`、`funa`、`wakasagi`)。ID の一覧とレベル・重量は 1 つのデータ(JSON の一覧、またはコード内の 1 つのテーブル)にまとめ、増減しやすくする。
- 各魚の JSON(`fish_profiles/<id>.json`)を作る。難易度はレベルから計算して焼き込む(あとで魚ごとに手調整できる):
  - `stamina = 80 + 8 × (L - 1)`
  - `dash_interval = round(75 - 1.5 × (L - 1))`
  - `dash_power = 0.8 + 0.04 × (L - 1)`
  - `tension_gain = 0.9 + 0.025 × (L - 1)`
  - `rarity`: Lv1〜5 = common、6〜10 = uncommon、11〜15 = rare、16〜20 = epic。
  - `xp = 10 + 6 × (L - 1)`、`weight_min` / `weight_max` は `fish-list.md`。
  - `level = L`、`bait_level = L`、`catch_weight` = 10。
- アイテムモデル: `item/generated` の親で、テクスチャは `fishinggui:item/<id>`。仮画像として、16×16 の同じ PNG を `textures/item/<id>.png` に全 56 種分置く。あなたの画像を同じファイル名で置くだけで差し替わる。
- 言語ファイル: 魚の名前(日本語と英語)。アクションバーのメッセージ。
- クリエイティブタブに、ミミズと全オリジナル魚を並べる。
- 魚は食べられない(焼いて食べる機能はバックログ)。

## 6. テスト

- `CatchSelectorTest`(固定シードまたは差し込める乱数で決定的に):
  - 狙うレベル T の重みが `0.5^k` に従う(多数回の試行で比率の範囲を確認、またはロジックを公開して重みを直接確認)。
  - 餌なしは常にレベル 1 だけ。`up` は餌なしでは 0。
  - 幸運で `up` が増える(上限 0.5)。
  - エントリのないレベルは飛ばされる。プールが 1 レベルだけなら、それが必ず選ばれる。
  - 餌と同じアイテムは約 1% だけ採用される。
  - レベル 20 では `T+1` を狙わない。
- `FishProfileParserTest`: `level`、`catch_weight`、`bait_level` の正常、省略、不正値。
- 実機: 餌なしで釣る→レベル 1 の魚だけ。ミミズ(Lv3 以上の釣りレベルで使用可)でレベル 3 以下の魚が、レベル 3 が多めに釣れる。レベル不足の餌でメッセージが出て餌が減らない。釣った魚を餌にすると、その魚はほぼ釣れない。クリエイティブタブに全アイテムが並ぶ。
