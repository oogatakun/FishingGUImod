# 釣りファイト mod 設計書

- 対象: Minecraft 1.20.1 / Forge 47.x / Java 17 / 公式(Mojang)マッピング
- mod ID: `fishinggui`
- 日付: 2026-11-02

## 1. 概要

バニラの釣りでアタリが出た後、専用のミニゲームGUIでテンションを管理しながら魚を釣り上げる mod。
右クリック長押しで巻き、テンションが上限を超えると糸が切れる。専用サーバー対応(判定はサーバー側)。

## 2. 全体の流れ

1. **キャスト**: バニラと同じ。オフハンドにエサがあれば装着して投げる。
2. **ヒット**: バニラのアタリが出た後の**最初の右クリック**でファイト開始。サーバーがセッションを作り、クライアントにテンションGUIを開く。アタリ中でない右クリックはバニラ処理のまま。
3. **ファイト**:
   - 右クリック**長押し**で巻く。魚の体力が減り、テンションが上がる。
   - 離すとテンションが下がるが、魚が逃げて体力が少し回復する。
   - 魚は時々**ダッシュ**してテンションが急上昇する。この間は離して耐える。
4. **決着**:
   - **成功**: stamina が 0 になると、釣果がバニラの釣りルートテーブルから生成される。
   - **失敗(糸切れ)**: tension が 100 に達すると、竿の耐久度を追加消費し、エサが消失する。
   - **中断**: ウキ消滅・竿の持ち替え・GUIを閉じる(ESC)・切断・死亡は失敗と同じ扱い。
5. **難易度**: アイテム種別(魚/ゴミ/宝物)とレア度で `FishProfile` が決まる。エサがレア度や暴れ方に影響する。

## 3. テンションモデル

サーバーが 20tick/秒で計算する。

状態値: `tension`(0〜100、100で糸切れ)、`stamina`(魚ごとの初期値、0で成功。目安 30〜100)。

| 状況 | tension / tick | stamina / tick |
|---|---|---|
| 巻く(長押し) | +1.5 | -1.0 |
| 離す | -2.0 | +0.3 |
| ダッシュ中(1〜2秒) | 上記に加えて +2.5 | 変化なし |

基準値。`FishProfile` の倍率で変わる。

魚の行動:
- 2〜5秒ごとにランダムでダッシュする(間隔と強さは魚による)。
- ダッシュの 0.5 秒前に予兆を出す(ゲージが震える、音)。
- tension 70 以上は危険ゾーン。ゲージが赤くなり、警告音が鳴る。

`FishProfile` のパラメータ: `stamina`, `dashInterval`, `dashPower`, `tensionGain`(倍率)。データパックの JSON で調整できる(Phase 2)。ゴミは弱く、宝物とレア魚は強い。

Phase 1 の既定値(`FishProfile.DEFAULT`): `stamina 100`、`dashInterval 70`(tick、平均。実際は 0.6〜1.4 倍でばらつく)、`dashPower 1.0`、`tensionGain 1.0`。

## 4. GUI

- 画面中央に縦のテンションゲージ。危険ゾーンは色分けし、現在値を表示。
- 魚の体力バーとダッシュ予兆のアイコン。
- 操作は右クリック長押しのみ。ESC は中断扱い。
- ゲームは止めない(マルチ対応のため時間は進む)。

## 5. エサ(新規アイテム)

- ミミズ(基本)、光る虫(レア度ブースト)、丈夫な練りエサ(ダッシュ弱め)の 3 種。
- オフハンドから装着。糸切れで消失し、成功でも 1 個消費する。

## 6. 技術設計

| パッケージ | クラス | 役割 |
|---|---|---|
| `fight` | `FightSession` | 1人分のファイト状態と 1tick 更新。**純Javaで、Minecraft に依存しない** |
| `fight` | `FishProfile` | 難易度 4 パラメータ。レア度・種別から決める |
| `fight` | `FightManager` | プレイヤーごとのセッション管理。サーバー tick で進行し、各種中断条件を監視 |
| `hook` | `FishingHookHandler` | Forge イベントで右クリックを横取りし、ヒット中ならファイト開始。Access Transformer で `FishingHook` の `nibble` 等を参照 |
| `hook` | `CatchResolver` | 成功時にバニラの釣りルートテーブルから報酬を生成し、ウキの位置からプレイヤーへ飛ばす |
| `item` | `BaitItem` ほか | エサ 3 種。装着と消費 |
| `net` | パケット 3 種 | S→C `FightStart`(魚情報)、S→C `FightState`(tension / stamina / 予兆 / ダッシュ中 / phase。毎tick)、C→S `ReelInput`(1バイトの action: `RELEASE` / `REEL` / `ABORT`。変化時に送り、GUI が開いている間は 10tick ごとにキープアライブとして再送する)。パケットは 3 種のまま。`FightState` の phase が `ACTIVE` 以外(`SUCCESS` / `FAILED`)なら、クライアントは GUI を閉じる |
| `client` | `FightScreen` | ゲージ描画、音、入力検知 |
| `data` | `FishProfileLoader` | データパック JSON から難易度を読み込む |

採用アプローチ: **Forge イベント+Access Transformer**(バニラの竿・他 mod と互換性が高く、Mixin 不要)。
不採用: Mixin による `FishingHook` 書き換え(他 mod と競合するリスク)、専用の竿/ウキエンティティ(作る量が多く、バニラの竿が使えなくなる)。

データフロー:
`右クリック → HookHandler がセッション開始 → FightStart でGUI表示 → ReelInput(長押し) → サーバーが毎tick FightSession.tick() → FightState をクライアントへ → 成功/失敗で終了 → CatchResolver または失敗ペナルティ`

## 7. エラー処理・チート対策

- 入力はサーバーが検証する。1tick に受け付ける入力は最大 2 つ(`MAX_INPUTS_PER_TICK`)で、それを超える連打変化は無視する。
- 入力が 40tick(`INPUT_TIMEOUT_TICKS`)途絶えたら、離している扱いにする。クライアントのキープアライブ(10tick ごと)があるので、通常の長押し中は途絶えない。
- 竿の持ち替え・ウキ消滅・プレイヤー死亡は失敗扱いで終了する。

## 8. テスト方針

- `FightSession` は JUnit で単体テストする。確認項目は、巻き続けたら糸切れ、離し続けたら体力回復、ダッシュ時の挙動、成功条件。
- Forge 連携の GameTest(`runGameTestServer`)は Phase 1 の対象外とし、Phase 2 で再検討する。Phase 1 は単体テストと、計画書の手動チェックリスト(実機・専用サーバー)で確認する。
- GUI の見た目は実機で手動確認する。

## 9. 段階(スコープ分割)

1. **Phase 1**: ファイトのコア(セッション、バニラ報酬、GUI、パケット)。エサなし、難易度は固定値でよい。
2. **Phase 2**: エサアイテム、データパック難易度、失敗ペナルティ(エサ消失・耐久追加消費)。
3. **Phase 3**: オリジナル魚アイテムの追加。

各 Phase ごとに計画→実装を行う。

## 10. 既知の制限(Phase 1)

- アタリ中の最初の右クリックで、クライアントがバニラのウキ回収音と腕振りを再生してしまう。サーバー専用の `nibble` 値がクライアントから見えず、アタリ中かどうかを判別できないため。
- ファイトはバニラのアタリ猶予時間より長引くことがあり、その間ウキのアニメーションが不自然に見える場合がある。
- `CatchResolver` は、`ItemFishedEvent` がキャンセルされた場合に竿の耐久度を消費しない。また、回収音のピッチは固定値(成功 1.0、失敗 0.6)。
